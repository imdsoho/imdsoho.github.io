##### 스레드 안전하지 않습니다

> 멀티스레드 환경에서 여러 스레드가 동시에 같은 데이터나 함수에 접근할 때, 데이터 손상, 정합성 파괴, 예상치 못한 오류가 발생할 수 있음을 의미

- 원인: 여러 스레드가 공유 자원(static 변수, 인스턴스 변수 등)을 수정하거나, 한 스레드가 읽는 중에 다른 스레드가 데이터를 바꾸는 경우
- 결과: 데이터 정합성 깨짐, 예상치 못한 프로그램 결과, 무한 대기 (Deadlock) 등
- 해결책: synchronized 키워드 사용, Lock 객체 활용, 불변 객체(Immutable Object) 사용, 원자적(Atomic) 클래스 사용 등

##### [python] coroutine task 객체를 스레드 안전하게 사용하는 방법

> Python의 asyncio.Task 객체는 기본적으로 스레드 안전(Thread-safe)하지 않습니다.  
> Task는 단일 이벤트 루프 내에서 코루틴을 실행하기 위해 설계되었기 때문에, 서로 다른 스레드에서 Task 객체를 직접 조작하면 Race Condition이나 데드락이 발생할 수 있습니다.

1. asyncio.run_coroutine_threadsafe 활용
<pre>import asyncio
import threading
import time

async def my_task(n):
    await asyncio.sleep(1)
    return f"Task {n} finished"

def start_loop(loop):
    asyncio.set_event_loop(loop)
    loop.run_forever()

# 1. 새로운 스레드에서 이벤트 루프 실행
new_loop = asyncio.new_event_loop()
t = threading.Thread(target=start_loop, args=(new_loop,), daemon=True)
t.start()

# 2. 다른 스레드(예: 메인 스레드)에서 코루틴 제출
# asyncio.run_coroutine_threadsafe는 thread-safe합니다.
future = asyncio.run_coroutine_threadsafe(my_task(1), new_loop)

# 3. 결과 대기 (block되지 않음)
result = future.result() 
print(result)
</pre>

2. loop.call_soon_threadsafe를 이용한 Task 취소
- Task 객체 자체를 직접 취소(task.cancel())하지 말고, 이벤트 루프에 취소 요청을 전달합니다. 
<pre>def cancel_task_from_thread(loop, task):
    # 직접 task.cancel()을 부르지 않고 안전하게 전달
    loop.call_soon_threadsafe(task.cancel)
</pre>

3. 스레드 간 데이터 통신: asyncio.Queue
- 스레드 안전하게 데이터를 전달하려면 asyncio.Queue를 사용하며, 다른 스레드에서 데이터를 넣을 때는 loop.call_soon_threadsafe를 통해 put_nowait을 호출해야 합니다. 
<pre># 외부 스레드 -> 비동기 태스크로 데이터 전달
def send_data_to_async(loop, queue, data):
    loop.call_soon_threadsafe(queue.put_nowait, data)
</pre>

> 요약 및 주의사항
> - 절대 금지: 다른 스레드에서 task.cancel(), task.result() 등을 직접 호출하지 않는다.
> - 해결책: 항상 asyncio.run_coroutine_threadsafe나 loop.call_soon_threadsafe를 사용한다.
