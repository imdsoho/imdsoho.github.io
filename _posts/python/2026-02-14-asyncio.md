2. coroutine
   - “코루틴” 이라는 용어는 두 가지 밀접한 관련 개념:  
     - 코루틴 함수: async def 함수
     - 코루틴 객체: 코루틴 함수를 호출하여 반환된 객체

3. Tasks
   - coroutine을 동시에 `예약(to schedule)`하는데 사용
   
   <pre>import asyncio  
   async def main():
        print('hello')
        await asyncio.sleep(1)
        print('world')  
   
   >>> asyncio.run(main())   
   
   단지 코루틴을 호출하는 것으로 실행되도록 to schedule 하는 것은 아닙니다:
   >>> main()
   coroutine object main at 0x1053bb7c8
   
   코루틴을 실제로 실행하기 위해, asyncio가 다음과 같은 메커니즘을 제공합니다: 
   최상위 진입점 “main()” 함수를 실행하는 asyncio.run() 함수
   </pre>
   
   - 태스크는 코루틴을 동시에 to schedule 하는 데 사용됩니다. 
   - 코루틴이 asyncio.create_task()와 같은 함수를 사용하여 태스크로 싸일 때 코루틴은 <b>곧 실행되도록</b> 자동으로 예약됩니다:

   ###### create_task와 taskGroup의 차이점
   > asyncio.create_task는 개별 코루틴을 비동기 태스크로 즉시 스케줄링하여 독립적으로 실행하는 (이전)방식  
   > asyncio.TaskGroup(Python 3.11+)은 구조적 동시성(Structured Concurrency)을 도입하여 여러 관련 태스크를 하나의 컨텍스트 내에서 관리하고, 
   > 오류 발생 시 안전하게 멈추는(cancel) 더 안전한 방식
   
   - 구조적 관리: TaskGroup은 async with 문을 사용하여 블록 종료 시 모든 태스크 완료를 보장하지만, create_task는 독립적이라 관리가 수동적임
   - 오류 처리 (Safety): TaskGroup은 한 태스크가 실패하면 나머지를 자동으로 취소하여 오류가 전파되는 것을 막지만,   
   create_task는 예외 발생 시 개별적으로 처리해야 하므로 좀비 태스크가 생길 수 있습니다.
   - 사용법: TaskGroup은 컨텍스트 매니저를 통해 코드가 직관적이며 오류 처리가 내장되어 있습니다. 


4. Futures
   - Future는 비동기 연산의 최종 결과를 나타내는 특별한 `저수준` Awaitable 객체입니다.
   - Future 객체를 기다릴 때, 그것은 코루틴이 Future가 다른 곳에서 해결될 때까지 기다릴 것을 뜻합니다.

5. event loop
   > 파이썬의 이벤트 루프(Event Loop)는 asyncio 모듈의 핵심 엔진
   > 비동기 작업(Coroutine)을 스케줄링하고 실행하며 관리하는 무한 루프입니다.
   > 단일 스레드에서 I/O 작업(네트워크, 파일 등)이 완료되기를 기다리지 않고, 
   > 작업이 준비될 때까지 다른 작업을 처리하는 논블로킹(Non-blocking) 방식의 동시성을 가능하게 합니다. 

   - 비동기 관리자: async/await로 작성된 코루틴이 실행 대기 큐(Task Queue)에 쌓이면, 이벤트 루프가 이를 순차적으로 가져와 실행합니다.
   - 논블로킹 실행: I/O 작업(예: DB 조회)이 발생하면 해당 작업을 시스템에 맡기고, 이벤트 루프는 멈추지 않고 즉시 다음 작업을 처리합니다. 
   - 콜백 처리: 비동기 작업이 완료되면 등록된 콜백 함수가 이벤트 루프에 의해 실행되어 결과를 처리합니다. 
   - asyncio.run(): 파이썬 3.7+에서 asyncio.run()을 통해 자동 생성 및 실행되어 메인 진입점으로 사용됩니다. 
   - 상호작용: GUI 환경에서는 사용자 입력(클릭, 키 입력)을 처리하는 루프로도 작동합니다

6. ProcessPoolExecutor
   - 병렬 처리: 여러 CPU 코어를 사용하여 작업을 동시에 실행
   - 사용 방식: with ProcessPoolExecutor() as executor: 문맥 관리자를 권장하며, map 또는 submit 메서드로 함수를 실행
   - 적합한 작업: 데이터 분석, 영상/이미지 처리, 대량의 계산 등
   - 주의사항: 프로세스 생성 비용이 있으므로 짧은 작업보다는 긴 작업에 적합하며, 데이터 직렬화(pickling) 비용 발생
