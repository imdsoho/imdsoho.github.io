##### 실시간 응답속도가 느린 분석 서비스에서 UX를 향상시키는 방법

> “지금 무엇을 하고 있는지”, “얼마를 더 기다려야 하는지”, “필요한 정보가 무엇인지” 를 보여주는 것  
> 빠르게 만드는 것이 아니라, 기다림을 통제 가능하고 의미 있게 만드는것

- 사용자의 체감 속도를 향상시키는 UX 디자인 적용
- 기다림을 제거하는 것이 아니라, 기다림을 관리/분해/가시화 하는 것

1. 실제 속도를 올리는 기술적 최적화
2. 로딩 상태의 투명한 시각화
    - Skeleton UI 사용 - 데이터가 들어갈 자리에 레이아웃을 미리 보여주어 로딩 중임을 명시
    - 진행 상황 표시 - Progress Bar
    - 구체적 로딩 메시지 - “데이터가 많아 시간이 소요됩니다.” 등
3. ~~점진적 데이터 표시 (빠른 초기 응답)~~
    - ~~Lazy Loading~~
    - ~~핵심 지표 우선 로딩~~
4. 사용자 인터랙션 최적화
    - 초기 필터/기본값 설정
    - 비동기식 UI - 사용자기 필터를 적용할 때 비동기 방식으로 변경된 부분만 수정
    - ~~취소/재시도 버튼~~
5. 사용자 인지 관리
    - 데이터 사전 예측

    - 데이터 집계 - 실시간 계산 대신 미리 집계된 데이터를 사용
    - 불필요한 요소 제거


##### CPU Bound 동기 분석 서비스에서 UX를 향상시키는 방법

> ~~계산을 빨리 끝내기~~  
> 기다림을 덜 고통스럽게 만들기  
> 브라우저/서버가 멈춘 느낌을 없애기

1. "동기"를 유지하면서 사실상 분할 실행
   - Streaming response (SSE)
     - 같은 HTTP 커넥션을 유지한채 "단계  로그/중간 지표"를 보냄
     - UX 화면이 멈추지 않고 "진행 중" 확인
2. 단계 체크 리스트 + 현재 단계 설명
   - 실시간 로그(요약형): "특징 수 50k -> 필터링 12k"과 같은 메시지 노출
   - 예상 소요시간(ETA): 과거 실행 기록 기반(간단 회귀/룩업) 정보 제공
3. 브라우저/서버가 멈춘 느낌 제거
   - Frontend
     - heavy render(대규모 표/plot)는 Web Worker로 분리
   - Backend
     - 요청 타임아웃/프록시 타임아웃(nginx, LB)회피
       - 주기적 flush(스트리밍)로 idle timeout 방지
     - 계산 중 heartbeat 전송
4. 계산 자체를 UX 관점으로 재구성
   - 분석 옵션 선택
     - fast mode/ standard mode/ exhaustive mode
5. 캐시/재사용 
   - 동일 입력+파라미터는 즉시 반환
   - "유사 분석" 재사용
     - preprocessing 결과 캐시
     - feature selection, normalization 등 단계 캐시
